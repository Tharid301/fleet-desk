เอกสารนี้ออกแบบให้ยื่นให้โปรแกรมเมอร์คนใหม่อ่านแล้วเข้าใจระบบภายใน 10-15 นาที
สถานะ ณ 18 ก.ย. 2569 · ไฟล์หลัก `fleet-desk-prototype.jsx` (4,357 บรรทัด · 92 คอมโพเนนต์)

เอกสารอื่นที่เกี่ยวข้อง:
- `fleet-db-schema.md` — โครงสร้างฐานข้อมูลสำหรับระบบจริง
- `fleet-desk-buildlog.md` — ประวัติการตัดสินใจและบั๊กที่เจอ
- `คู่มือทำเว็บ-สำหรับเจ้าของธุรกิจ.md` — พื้นฐานสำหรับคนไม่เขียนโค้ด

## 1. ระบบนี้คืออะไร

ระบบจัดการธุรกิจรถเช่ารายวัน สำหรับกองรถขนาดเล็ก (ปัจจุบัน 8 คัน)

รองรับทั้งรถของบริษัทเองและรถฝากของพาร์ทเนอร์ (คิดคอมมิชชั่นแยก)

## 2. สถานะปัจจุบัน — สำคัญที่สุดที่ต้องรู้ก่อน

```
┌─────────────────────────────────────────┐
│  Frontend (React)          ✅ มีแล้ว     │
│  ↓                                       │
│  Backend                   ❌ ยังไม่มี   │
│  ↓                                       │
│  Database                  ❌ ยังไม่มี   │
└─────────────────────────────────────────┘
```

**ข้อมูลทั้งหมดเก็บใน `localStorage` ของเบราว์เซอร์** (key: `fleetdesk_v1`)

ผลที่ตามมา:
- ข้อมูลอยู่เฉพาะเครื่องที่กรอก — ไม่แชร์ระหว่างผู้ใช้
- พื้นที่จำกัด ~5 MB → เก็บงานที่มีเอกสารครบได้เพียง **3-5 งาน**
- Safari ลบทิ้งถ้าไม่เข้าเว็บเกิน 7 วัน (ITP)
- การตรวจสิทธิ์อยู่ที่ frontend → **ข้ามได้ด้วย devtools**

**นี่คือ prototype ที่ใช้ทดสอบ flow และกฎธุรกิจ ไม่ใช่ระบบที่พร้อมรับงานจริง**

## 3. โครงสร้างการทำงาน

### 3.1 ทางเข้า (Routing)

```
HomePage (หน้าแรกบริษัท)  ← ค่าเริ่มต้นเมื่อเปิดเว็บ
   │
   ├─ "เช็ครถว่าง & จองเลย" → CustomerAvailabilityView (สาธารณะ ไม่ต้องล็อกอิน)
   │                              └─ ส่งคำขอ → สร้าง booking status="pending"
   │
   └─ "สำหรับเจ้าหน้าที่" (footer) → LoginScreen → App (ระบบจัดการ)
                                                      └─ logout → กลับ HomePage
```

ควบคุมด้วย state 2 ตัวใน `App`: `entry` ("home" | "staff") และ `publicMode` (boolean)

**ตอนทำระบบจริง** ต้องแยกเป็น 2 URL: `/` = หน้าลูกค้า · `/admin` = หน้าเจ้าหน้าที่

### 3.2 แท็บและสิทธิ์

| แท็บ | หน้าที่ | owner | staff | accountant |
|---|---|---|---|---|
| กองรถ | ข้อมูลรถ ค่าเช่า มัดจำ วันหมดอายุเอกสาร | แก้ได้ | แก้ได้ | ดูอย่างเดียว |
| คิวงาน | ปฏิทิน 2 มุมมอง (รายการ/ตารางรวม) + งานเคลียรถ | ✓ | ✓ | — |
| งานเช่า | คำขอ → ยืนยัน → ส่งมอบ → ปิดงาน | แก้ได้ | แก้ได้ | — |
| ประวัติ | งานที่ปิด/ยกเลิก + filter + export | ✓ | ✓ | ✓ |
| เบิกเงิน | พนักงานยื่นคำร้อง → เจ้าของอนุมัติ → จ่ายคืน | ✓ | ✓ | ✓ |
| บัญชี | เงินสด · ความต้องการตลาด · รายจ่าย · P&L · พาร์ทเนอร์ | ✓ | — | ✓ |

กำหนดที่ `ROLE_TABS` และ `TAB_META` (บรรทัดต้นไฟล์)

### 3.3 Responsive

เลือกเลย์เอาต์ด้วย JavaScript (`window.innerWidth >= 1024`) ไม่ใช่ CSS media query
เพราะต้องรองรับปุ่มสลับเลย์เอาต์เอง (เก็บใน localStorage key `fleetdesk_layout`)

| | มือถือ (<1024px) | คอม (≥1024px) |
|---|---|---|
| เมนู | แท็บด้านบน | Sidebar ซ้าย |
| กองรถ | การ์ด 2-3 คอลัมน์ | การ์ด 4-5 คอลัมน์ |
| งานเช่า/ประวัติ | การ์ดแนวตั้ง | ตาราง 7 คอลัมน์ |
| ปฏิทิน | 7 วัน | 14 วัน |

## 4. โครงสร้างข้อมูล (State)

ทั้งหมดอยู่ใน `App` component และ persist ลง localStorage เป็นก้อนเดียว

| State | เก็บอะไร | หมายเหตุ |
|---|---|---|
| `cars` | ข้อมูลรถ ราคา มัดจำ ค่าใช้จ่าย ค่างวด วันหมดอายุเอกสาร | |
| `bookings` | การจองทุกสถานะ | pending / active / completed / cancelled |
| `scheduleEvents` | รายการในปฏิทิน (1 แถว = 1 วัน) | สร้างอัตโนมัติจาก booking |
| `claims` | คำร้องเบิกเงินพนักงาน | pending / approved / paid / rejected / cancelled |
| `otherExpenses` | รายรับ-รายจ่ายนอกเหนือค่าเช่า | |
| `categories` | หมวดหมู่รายรับ-จ่าย (แก้ไขได้) | |
| `overhead` | เงินเดือน + ค่าใช้จ่ายส่วนกลาง | |
| `accounts` | บัญชีผู้ใช้ | รหัสผ่านไม่เข้ารหัส — demo เท่านั้น |
| `termsText`, `bankInfo` | เงื่อนไขสัญญา + เลขบัญชี (แก้ไขได้) | |

### ความสัมพันธ์สำคัญ

```
booking ──(expandBookingToEvents)──> scheduleEvents หลายแถว
                                      ├─ type "booked"  (ช่วงเช่า)
                                      └─ type "clean"   (เคลียรถ 1 ชม. หลังคืน)
```

- 1 booking แตกเป็น scheduleEvents หลายแถว (วันละแถว) ผูกกันด้วย `bookingId` และ `groupId`
- event ที่มี `bookingId` **ห้ามแก้ในปฏิทิน** ต้องไปแก้ที่ booking แล้วระบบสร้างใหม่
- `ensureCleanBuffers()` เติมช่วงเคลียรถให้ข้อมูลเก่าที่บันทึกไว้ก่อนมีฟีเจอร์นี้ (idempotent)

## 5. กฎธุรกิจที่ฝังอยู่ในโค้ด

**ห้ามแก้โดยไม่ได้รับคำสั่ง — เป็นข้อตกลงที่ผ่านการยืนยันแล้ว**

### 5.1 การคิดค่าเช่า (`calcDuration` / `calcBookingTotal`)

1. ไม่ถึง 24 ชม. = คิด 1 วันเต็ม
2. เกิน 1 วัน เศษเกิน 3 ชม. → ปัดขึ้นเป็น 1 วัน
3. เกิน 1 วัน เศษไม่เกิน 3 ชม. → คิดรายชั่วโมง (เศษนาที <30 ปัดลง, ≥30 ปัดขึ้น)

**เทสต์ที่ต้องผ่าน 5 เคส:**

| รับ | คืน | ผลลัพธ์ |
|---|---|---|
| 8 ส.ค. 09:00 | 10 ส.ค. 11:00 | 2 วัน 2 ชม |
| 8 ส.ค. 09:00 | 10 ส.ค. 07:00 | 2 วัน |
| 8 ส.ค. 09:00 | 8 ส.ค. 18:00 | 1 วัน |
| 8 ส.ค. 09:00 | 9 ส.ค. 06:00 | 1 วัน |
| 8 ส.ค. 07:00 | 9 ส.ค. 12:00 | 2 วัน |

- คืนช้า → คิดตามเวลาจริง (`calcActualBookingTotal`)
- คืนเร็ว → ยึดตามที่จอง ไม่ลดราคา
- ตั้งราคาเฉพาะรายได้ (`customDailyRate`) เช่น ลดให้ลูกค้าระยะยาว

### 5.2 การเงิน — เงินสด ≠ กำไร

แยกเป็น 2 ฟังก์ชันโดยตั้งใจ:

| | `computePnL` (กำไร) | `computeCashFlow` (เงินสด) |
|---|---|---|
| ค่างวดรถ | เฉพาะดอกเบี้ย | **เต็มจำนวน** |
| ค่าเสื่อมราคา | เป็นรายจ่าย | ไม่มีเงินออก |
| ซื้อรถ | ไม่กระทบ | เงินออกเต็มจำนวน |
| เจ้าของถอนเงิน | **ไม่กระทบ** | เงินออก |
| มัดจำค้ำประกัน | ไม่ใช่รายได้ | เงินเข้า (เป็นหนี้สิน) |

**กระแสเงินสดแบ่ง 3 กลุ่ม** (`FLOW_TYPES`): ดำเนินงาน (กระทบกำไร) · ลงทุน · จัดหาเงิน (ไม่กระทบกำไร)

**คำร้องเบิกเงิน:** เป็นรายจ่ายตอน **อนุมัติ** (มีใบเสร็จแล้ว) · ตัดเงินสดตอน **จ่ายคืน** · ช่วงคาบเกี่ยวแสดงเป็น "ค้างจ่ายคืนพนักงาน"

### 5.3 การปิดงาน

ปิดได้ต่อเมื่อครบ **4 เอกสาร**: สลิปโอนจอง + สัญญาที่เซ็น + รูปส่งมอบรถ + สลิปคืนมัดจำ
งานที่ปิด/ยกเลิกแล้ว = อ่านอย่างเดียว ย้ายไปแท็บประวัติอัตโนมัติ

### 5.4 กฎฝั่งลูกค้า

- ต้องแนบ**ตั๋วเดินทาง**ที่มีชื่อผู้จอง (ถ้าไม่มี → ให้ติดต่อบริษัทโดยตรง)
- ต้องรับทราบเงื่อนไขสัญญาก่อน
- ต้องแนบ**สลิปมัดจำ**ก่อนส่งคำขอ
- ส่งคำขอแล้ว **ล็อกคิวทันที** กันจองซ้ำ (แม้ยังไม่ยืนยัน)

## 6. ความเป็นส่วนตัว (PDPA) — จุดที่ต้องระวังที่สุด

**เคยเกิดข้อมูลรั่วจริงมาแล้ว 1 ครั้ง** — หน้าสาธารณะแสดงชื่อและเบอร์โทรของลูกค้ารายอื่น

**วิธีป้องกันปัจจุบัน:** `CustomerAvailabilityView` สร้าง `publicEvents` ที่ตัดข้อมูลระบุตัวตนออกทั้งหมด
(เหลือเฉพาะ carId, date, startHour, endHour, kind) **ก่อน** ที่ UI จะเข้าถึงได้

```js
const publicEvents = scheduleEvents.map((e) => ({
  carId: e.carId, date: e.date, startHour: e.startHour, endHour: e.endHour,
  kind: e.type === "booked" ? "taken" : e.type === "clean" ? "prep" : "unavailable",
}));
```

**ทุกฟังก์ชันในหน้าลูกค้าต้องอ่านจาก `publicEvents` เท่านั้น ห้ามแตะ `scheduleEvents` ดิบ**

มีเทสต์ถาวร `privacy-test.cjs` ตรวจว่าชื่อ/เบอร์โทรลูกค้า 14 ค่าไม่โผล่บนหน้าสาธารณะ

**⚠️ ข้อจำกัด:** นี่กันได้แค่ระดับ UI — ข้อมูลดิบยังอยู่ในเบราว์เซอร์ อ่านได้ด้วย devtools
**การแยกจริงต้องทำที่ backend** — endpoint ฝั่งลูกค้าต้องไม่ส่งข้อมูลการจองมาตั้งแต่แรก (ใช้ RLS)

## 8. Build และ Deploy

```bash
# 1. bundle (target es2019 — สำคัญ ห้ามใช้ esnext เพราะ Safari เก่า parse ไม่ผ่าน)
npx esbuild entry.jsx --bundle --format=iife --minify \
  --loader:.jsx=jsx --jsx=automatic --target=es2019 \
  --outfile=bundle.js --define:process.env.NODE_ENV='"production"'

# 2. compile Tailwind (ห้ามใช้ CDN ใน production)
npx tailwindcss -c tailwind.config.js -i tw-input.css -o tw-out.css --minify

# 3. รวมเป็น HTML ไฟล์เดียว (ฝัง CSS + JS + error catcher)
```

**ผลลัพธ์:** ไฟล์เดียว ~1.19 MB เปิดได้โดยไม่ต้องต่อเน็ต

**Error catcher ในหน้า HTML:** ดัก `window.onerror` + `unhandledrejection` + timeout 6 วินาที
แสดง error บนหน้าจอพร้อม userAgent — เพราะบนมือถือเปิด devtools ไม่ได้
**ตัวนี้คือสิ่งที่ทำให้เจอสาเหตุหน้าขาวได้ภายในรอบเดียว ห้ามเอาออก**

**ข้อจำกัดของ Claude Artifact:** ถูกบล็อกไม่ให้เรียก API ภายนอก
→ **ถ้าจะต่อฐานข้อมูลจริงต้องย้ายไป Vercel/Netlify**

## 10. สำหรับโปรแกรมเมอร์ที่รับงานต่อ

**อ่านตามลำดับนี้:**
1. เอกสารนี้ (ภาพรวม)
2. `fleet-db-schema.md` (โครงสร้างข้อมูลเป้าหมาย)
3. `fleet-desk-buildlog.md` (ทำไมถึงตัดสินใจแบบนี้ + บั๊กที่เคยเจอ)

**ข้อควรระวัง:**
- กฎธุรกิจในหัวข้อ 5 ผ่านการยืนยันกับเจ้าของแล้ว **ห้ามเปลี่ยนเอง**
- อย่าประกาศ component ข้างใน component body (เคยทำให้ฟอร์มพิมพ์ได้ตัวเดียว)
- อย่าวาง React hook หลัง early return (เคยทำให้ crash ตอนสลับหน้าจอ)
- เงินต้องเป็นทศนิยม 2 ตำแหน่งเสมอ (`fmt`) · จำนวนนับใช้ `fmtInt`
- วันที่ห้ามใช้ `toISOString()` (timezone เพี้ยนที่ UTC+7) ใช้ `addDays()` ที่เขียนไว้แล้ว
